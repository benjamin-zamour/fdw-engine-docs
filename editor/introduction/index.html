The editor

The editor edits the levels of the engine: it opens a scene, shows it in a 3D viewport between its panels, and changes it with the tools of editing (selection, gizmos, undo). It runs in two hosts that share the same interface:

  • on the desktop, an Electron application: the engine renders natively, on Vulkan, into a window placed in the area of the viewport;
  • in the browser, a web page: the engine runs in the page and renders into a canvas, on WebGPU or WebGL2.

Here is the web one, live. Click the viewport, then drag with the right button to turn the camera, the wheel to zoom; a click selects an object, W, E and R choose the tool that moves, turns or scales it.

Open the editor in a page of its own

The next pages use it: Editing a level goes through its interface, Writing a plugin adds a command and a panel to it, and The native viewport tells how the desktop editor puts the engine in its window, and what it costs. Profiles and views makes a viewer of the same shell, and splits the viewport into views whose cameras move together.

Running it

Section titled “Running it”

In the browser, from the root of the repository:

The same editor is also built into this site: open it in a page of its own. Its layout is kept in IndexedDB; the files of the levels are opened and saved through the File System Access API (Chromium), else by an import and a download.

On the desktop (Linux, X11 or XWayland), with the native addons built, the Vulkan SDK, libX11 and libXext:

The editor of the desktop builds with the shared Electron toolchain (tools/electron, out of the npm workspaces), which npx nx run editor-desktop:install installs the first time. From a terminal of VS Code, unset ELECTRON_RUN_AS_NODE, which makes Electron start as Node.

The executable: a portable executable under Windows, an AppImage under Linux, with the addons, DXC and the programs of its scenes precompiled; it needs neither CMake, a compiler nor the Vulkan SDK.

Its programs are compiled by playing its scenes on an offscreen surface, on Vulkan and on Direct3D 12 (Windows): it needs a device, a GPU or a software one (lavapipe, WARP); node scripts/package.mjs --no-precompile ships none. The executable has no Dawn fallback: Dawn needs a Node of its own.

The backend

Section titled “The backend”

The variable FDW_BACKEND chooses the backend, read when the editor starts (by Vite for the web one). Without it, the first of each host; when the one asked for does not start, or is unknown, the other, and the status bar tells why.

Host FDW_BACKEND Fallback How the frames reach the screen
Desktop vulkan (default) dawn A swapchain on the window of the viewport, without copy
Desktop dawn A Node process of its own; each frame read back, copied in the window
Web webgpu (default) webgl2 The canvas of the viewport
Web webgl2 The canvas of the viewport

On the desktop, Dawn runs in a Node process of its own, which must be Node 24: FDW_NODE gives its path, else the node of the PATH. FDW_SCENE chooses the scene shown first: the level by default, or one of the demo scenes of the Scene menu (tps, physics, ocean…). FDW_PROFILE chooses the application on the shell: editor (by default), viewer or configurator (?profile= in the page of the web one); see Profiles and views.

What it is made of

Section titled “What it is made of”
  • The shell (EditorShell) is the whole interface, in React. It has no panel of its own: the viewport, the outliner, the inspector, the console, the menus of the level are plugins, built in; a host adds its own.
  • The engine is never in the hands of the interface. The page and the engine talk by messages (@fdw/editor-ui/protocol): the bounds of the viewport, the inputs, the commands on the level one way; the state of the engine and the projection of the level the other. On the desktop the engine runs in a utility process of Electron, and never blocks the interface; on the web it runs in the page, behind a MessageChannel.
  • A host gives the shell an EditorHost: the connection to the engine, the component of the viewport (given the id of the view it shows), the files, the storage of the layout, its plugins, its profile. The README of @fdw/editor-ui lists them for both hosts.
