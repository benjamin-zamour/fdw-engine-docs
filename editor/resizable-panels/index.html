Building resizable panels

This tutorial extends the panel of Writing a plugin. The result fits a small dock without hiding its last control, uses the editor’s dark theme for its options, and reveals long names without widening the layout. The same components work in the browser and in the desktop editor.

1. Let the content grow

Section titled “1. Let the content grow”

Replace the component registered by context.views.registerComponent with:

The shell wraps each view in a bounded scrolling container. An ordinary form does not need h-full or a fixed pixel height: its content grows naturally. If the dock becomes shorter, scroll over the panel to reach Last control.

For a canvas with a fixed toolbar and a scrolling sidebar, keep its outer h-full flex flex-col layout. Give the shrinking content region min-h-0 flex-1 overflow-auto. A flex child needs min-h-0 to shrink below its content height; a grid column needs minmax(0, 1fr) to shrink below its longest name. Do not hide overflowing form content with overflow-hidden.

2. Use a themed select

Section titled “2. Use a themed select”

Select opens a Radix list rather than an OS window. Both the trigger and the list follow the editor’s theme; the list stays inside the window and scrolls when there are many options. Use Enter or Space to open it, arrows to navigate, Enter to choose, and Escape to close without changing the value. Disabled options cannot be selected.

Use SelectOption, not native <option> children. onValueChange receives the chosen string; onChange is also available and receives { target: { value }, currentTarget: { value } }, not a DOM event. An empty string is a valid option value. The deprecated NativeSelect and NativeSelectOption names now alias these components, not OS selects.

3. Reveal long text

Section titled “3. Reveal long text”

Truncate shrinks within its column and shows an ellipsis. Hover over a clipped name, or focus it with Tab, to read the full text in a tooltip. There is no tooltip when the text already fits. tabIndex={0} makes static text keyboard reachable; tooltip can supply a description instead of the children’s text.

Lists and tooltips are portalled outside panel clipping. On the desktop, the shell exposes them above the native viewport through its existing viewport holes; a plugin needs no Electron-specific overlay code.

4. Check the small layout

Section titled “4. Check the small layout”
  1. Open the panel from View and make its dock shorter. Scroll to the last button: no control should require resizing the dock to reach it.
  2. Narrow the dock. Long names should show an ellipsis, not widen the panel. Hover or focus a name to read it in full.
  3. Open Quality, including near the edge of the window. Its list should use the dark theme, remain within the window, and accept a keyboard selection.
  4. Widen the panel again: names that fit should no longer need a tooltip.

For automated checks, chooseOption from @fdw/editor-ui/testing opens a select and chooses by option text or value in jsdom. Test scrolling and truncation in a real browser: jsdom has no layout and cannot prove that the last control is reachable or that text actually overflows.
