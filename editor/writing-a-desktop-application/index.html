Building a desktop application on the editor

A desktop application runs the editor’s shell in an Electron window and the engine in a process of its own, on Vulkan (Direct3D 12 under Windows). The engine draws into a native viewport, a child window of the Electron window placed over the area the shell reserves, without copying its frames. The page and the engine talk over a MessagePort; the main process only connects them.

This tutorial continues the web application tutorial: it reuses its profile, plugins and engine extension. Like it, it is the project the CI builds out of the repository, from the npm archives of the packages, then packages and starts.

1. Create the project

Section titled “1. Create the project”

Create an empty directory, then install the editor packages, the native viewport, React, Electron and the build tools:

@fdw/editor-native-viewport brings the viewport and the Vulkan and Direct3D 12 backends, and with them native addons (Node-API, for Node and Electron alike): its own, that of @fdw/engine-vulkan and, under Windows, that of @fdw/engine-d3d12, each with the shader compiler DXC. These archives are built per platform.

The entry point of the application, in package.json, is the main process electron-vite builds:

electron-vite builds the three parts of the application. The packages are bundled into them: the executable ships no node_modules, only the addons, beside the bundle (step 7).

2. Reuse the application

Section titled “2. Reuse the application”

Copy from the web tutorial, unchanged, the files that do not depend on the platform:

  • src/profile.ts, the profile;
  • src/extension.ts, the engine extension: here it runs in the engine process;
  • src/plugins/about.tsx, the plugin and its panel;
  • src/styles.css, the stylesheets of the editor and of the plugin package.

3. The main process

Section titled “3. The main process”

The main process opens the window, gives the page its services (storage, file dialogs) and starts the engine process, an Electron utility process. It tells the engine where the native addons are: in the resources of the executable once packaged, in the packages otherwise. At each page load, it gives the page and the engine the two ends of a MessageChannelMain.

The handlers trust the pages of the window: the application loads only its own pages, and Electron’s contextIsolation and sandbox stay on.

Section titled “5. The page”

6. The engine process

Section titled “6. The engine process”

The engine process runs a DesktopEngineSession: the scenes, the extensions of the plugins, the other views of the viewport. At init, it creates the native viewport in the window and starts Direct3D 12 on it under Windows, Vulkan elsewhere; at each connect, it talks to the new page.

When the backend does not start (no driver, no device), the session reports it to the page, whose status bar shows the reason. On a Windows machine without GPU, FDW_D3D12_ADAPTER=warp selects WARP, the software rasterizer of Windows.

The same in a few lines: @fdw/editor-electron

Section titled “The same in a few lines: @fdw/editor-electron”

The main process, the preload and the engine process above are the same for every application on the editor: @fdw/editor-electron holds them, with the fallback on Dawn, the checks of the senders of the messages and the paths of the packaged addons. The products of the repository (apps/viewer/desktop…) are built on it:

startElectronApplication expects electron-vite’s layout (out/main, out/preload, out/renderer). Write the processes yourself, as above, when the application needs another window or other services.

7. Run, build and package

Section titled “7. Run, build and package”

electron-builder makes the executable from the bundle (out/) and puts the addons in its resources, where the main process finds them:

release/ then holds an AppImage (Linux) or an installer (Windows), and release/linux-unpacked/ or release/win-unpacked/ the application unpacked; npx electron-builder --dir makes only the latter.

The platforms. The CI validates this project on Linux x64 (X11, or XWayland under Wayland; Vulkan) and Windows x64 (Win32; Direct3D 12, on WARP): installed from the archives, built, packaged, and started from the package, out of the repository. The archives of the native packages are those of one platform (os, cpu in their package.json): build the package of each platform on that platform. macOS is not supported.

The packages are not published on npm yet: node tools/sdk/pack.mjs --desktop packs them from the repository, and node tools/sdk/verify-external.mjs --desktop builds, packages and starts this tutorial with them. For the FDW editor itself, its Dawn fallback and its precompiled programs, see its implementation and the native viewport.
