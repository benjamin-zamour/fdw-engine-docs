From the library to the instance

A material made once serves many products: the same brushed copper, darker on a handle, rougher on a worn part. The material editor of The material editor keeps its materials in a library, exposes the few parameters a variant may change, and declines it in instances: a parent and values, never a copy of the graph. A configurator or a studio then changes those values only, and every instance follows its parent.

Here the editor opens on a library in memory: the brushed copper (its tint and roughness exposed) and a dark instance of it. Nothing is kept when the page is left.

Open the editor in a page of its own

1. A library

Section titled “1. A library”

The Library panel, at the left, shows the materials of a folder. On the desktop and in Chromium, File → Open a library folder… asks for one: it may hold folders of its own (metals/, woods/). Each material is a .material.json file, each instance a .material-instance.json file, and beside each its metadata (copper.material.json.meta): an id that never changes, its labels, what it references. The folder is the library: copy it, put it under version control, share it.

  • Search by words of the name, the folder or the labels; narrow by Label and by Kind (materials, instances).
  • Open an entry in a tab; Delete removes it from the folder, after asking: it cannot be undone.
  • The labels of an entry are edited in place, comma separated.
  • An entry whose parent or texture is no longer in the library says Broken link: nothing is removed, nothing is repaired in silence.

To put a material in it, show it, then Add the material shown: a folder, labels, Add to the library. Its thumbnail is the image of its preview. A material of the library is saved in it (File → Save the material, Ctrl+S), its thumbnail made again.

Try it: make a new material, add it in paints/ with the label glossy, then search glossy.

2. Exposing parameters

Section titled “2. Exposing parameters”

Not everything of a material should change: a configurator must not break it. The Parameters panel lists the uniforms of the material shown (its input.uniform nodes): check Exposed for those its instances may change, give each a Label and a range (Min, Max). They are part of the material, in its file and its history:

The other uniforms are the material’s own. An exposed parameter whose uniform is removed is a warning of the material’s problems.

3. Instances

Section titled “3. Instances”

In the library, New instance on the copper opens an instance in a tab: its parent’s graph, without a value of its own. Its Parameters are those its parent exposes: a slider in the range, numbers for a color. A value that differs from the parent’s is marked •, and Reset takes the parent’s back. Save writes the instance in the library, next to its parent: its parent and the values that differ, nothing else:

Change the parent (its graph, a default), save it: the instances open and unchanged follow it at once, and every instance reads it at its next opening. A value its parent no longer exposes (removed, renamed) is kept in the file, not applied, and said; a value out of its range is applied, and said.

Try it: open dark-copper, set its roughness to 0.9, save; then open the copper, change its streaks, save it: the instance changes too.

4. Flattening to textures

Section titled “4. Flattening to textures”

A material graph is code: a tool that only reads textures (a game engine, a web store) cannot run it. File → Flatten to textures… draws the maps of the material shown on a plane by the engine, its uv filling the image, and saves them in PNG: baseColor and emissive in sRGB; metallic, roughness, occlusion and normal in linear values, the normal in the tangent space of glTF. What the graph computes from the uv is flattened as it is; what it computes from the position or the view is that of the plane.
