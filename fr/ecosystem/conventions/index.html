Conventions

Langues

Section intitulée « Langues »
  • Code, commentaires, README et cette documentation : anglais.
  • Documents de conception (design/*.md) : français.

Code

Section intitulée « Code »
  • TypeScript en mode strict (tsconfig.base.json) : pas de variables locales inutilisées, pas de retours implicites, override obligatoire.
  • Formatage par Prettier, avec des guillemets simples : npx prettier --write <files>, ou npx nx format:write.
  • Lint par ESLint avec les règles Nx, dont les frontières de modules : un projet en importe un autre par son nom de paquet (@fdw/engine-core), jamais par un chemin relatif, et le déclare dans son package.json.
  • Code natif : C++20 pour les bibliothèques, C pour les bindings Node-API ; les bibliothèques exposent une API C dans native/include/fdw/.

Style d’écriture

Section intitulée « Style d’écriture »

Le code se lit comme de la prose, et ses commentaires disent pourquoi, pas quoi :

  • Des mots complets dans les noms : shadowAtlasSize, pas shAtlSz.
  • Les commentaires sont des phrases complètes, et courtes. Une API publique reçoit un commentaire TSDoc (/** … */) : la référence de l’API de ce site est générée à partir d’eux.
  • Alignez-vous sur le code environnant : sa densité de commentaires, son nommage, ses idiomes. Une modification doit donner l’impression d’avoir toujours été là.
  • Pas de code mort, pas de code commenté.

Tests

Section intitulée « Tests »

Chaque modification s’accompagne de ses tests : un test unitaire à côté du code (*.spec.ts), et un test de la suite de rendu lorsqu’elle change ce qui est dessiné. Voir Tests.

Commits

Section intitulée « Commits »

Conventional commits, avec le paquet comme scope :

feat, fix, test, docs, refactor, perf, chore. Le message dit ce qui change pour l’utilisateur du code.

Documentation

Section intitulée « Documentation »

Une modification qui ajoute ou modifie une fonctionnalité met à jour :

  • les commentaires TSDoc de son API ;
  • le README.md de son paquet ;
  • les pages de ce site qui la décrivent : tutoriels, guides ;
  • son document de conception, si elle change une décision.

Où va une page et ce que déclare son frontmatter : Documentation.
