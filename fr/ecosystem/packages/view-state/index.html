The view state: how a model is looked at — visibility, looks, annotations, views, sections.
Product Ecosystem
Visibility Public: Meant to be used by applications and plugins.
Domains Viewing and embedding, Text, drawing and inspection
Dependencies capabilities
Dependents design-review, editor-ui, engine-dataviz, engine-measure
Tests test-unit (npx nx run view-state:<target>, the families of the CI in Testing)
API API reference
Source shared/view-state

The view state of the platform: how a model is looked at, not what it is. The elements hidden, isolated (the others hidden or ghosted), colored; the annotations (the measures, and the types the plugins declare: anchored comments, probes); the camera views; the sections and their limits. In memory, pure TypeScript, without the GPU; the model is never changed to be looked at. Design: design/p26-platform.md §7 and §13 (in French). Guide: The view state in the documentation.

  • References (ElementRef): the path of ids of an element (the instance path: the stable ids of a level, those of the pivot for a model opened) and its source key, scoped by its model. resolve(index) finds the elements by their ids, then by their key; a reference found by its key takes the new ids, and a source-key-fallback diagnostic says so; one found nowhere stays, with an unresolved.
  • Annotations: types declared by plugins (AnnotationType: an id, a version, write, read), through the view-state.annotation capability of @fdw/capabilities, their code loaded at the first reading. Data checked by a round trip when added; an annotation of an unknown type, or of a later version, is kept as read and written back unchanged.
  • Explosion: an exploded view, a displacement of the instances (setExplosion): radial, axial, by levels of the tree or manual (offsets by reference), a factor from 0 to 1, a spread, traces; explosionOffsets(tree, explosion) gives the displacement of each element of a tree with bounds. A state with an explosion is written as version 2.
  • Sections: planes in union within a section, sections in intersection; the section box preset; limits (sections and planes enabled) beyond which an addition throws limit.
  • JSON: toJSON, load, ViewState.read (fdw.view-state, version 1, or 2 with an explosion), with typed diagnostics; ViewStateError with a code.
  • Files: ViewStatePersistence, the exporters and importers declared by plugins (view-state.exporter, view-state.importer: their formats, extensions, form and the parts they hold), with a ViewStateReport in permissive or strict mode: what an exporter does not write, what an importer or the reading leaves out, is a line; in strict mode the first loss throws, nothing written, the state unchanged. The default plugin, the companion file (bracket.glb.view.json): the whole state as JSON beside the model, readable, the same bytes for the same state (a diff shows the changes only), the annotations of unknown types written back.
