Builds natifs

Deux paquets contiennent du code natif : engine-native (fenêtres sur SDL3, audio sur miniaudio) et engine-vulkan (le backend Vulkan). Chacun a un répertoire native/ compilé par CMake dans build/, par le script partagé tools/native/build-addon.mjs.

Prérequis

Section intitulée « Prérequis »
  • CMake 3.24 ou ultérieur, et un compilateur C/C++20 : GCC ou Clang, Visual Studio 2022 ou ultérieur (sa charge de travail C++) sous Windows.
  • Sous Linux, les paquets de développement dont SDL3 a besoin pour ses backends vidéo : X11 et/ou Wayland, comme pour tout build de SDL.
  • Rien pour les en-têtes Node-API : ils viennent de la dépendance de développement node-api-headers, avec le fichier .def dont CMake tire la bibliothèque d’import de node.exe sous Windows. NODE_API_INCLUDE_DIR les remplace.
  • Pour Vulkan, le SDK Vulkan, 1.3 ou ultérieur.

SDL3 et miniaudio sont téléchargés par CMake (FetchContent) lors du premier build, et liés statiquement : l’addon n’en dépend pas à l’exécution. miniaudio charge le système audio de la machine à la création d’un moteur (PulseAudio ou ALSA sous Linux), et se replie sur un périphérique nul sans lui.

Structure d’un paquet natif

Section intitulée « Structure d’un paquet natif »
  • La bibliothèque fait le travail et ne sait rien de Node ; le binding convertit les arguments et les erreurs.
  • La partie TypeScript charge l’addon à la demande (loadAddon()), et les tests peuvent le remplacer (setAddon()) par un mock.
  • Les objets Vulkan sont identifiés par des identifiants entiers côté TypeScript ; les images sont transmises sous forme de tableaux de mots de commande de 32 bits.

Portabilité

Section intitulée « Portabilité »

Le code natif est portable par construction : CMake, C++20 sans API système, SDL3 pour les fenêtres et les handles natifs, dépendances téléchargées plutôt que prises dans le système. Ce qui dépend de la plateforme — handles de fenêtre, chemins de bibliothèques — reste cantonné à quelques endroits isolés. Linux et Windows sont construits et testés en CI (Windows : Vulkan sur lavapipe, Direct3D 12 sur WARP, FDW_D3D12_ADAPTER=warp sur une machine sans GPU) ; macOS (via MoltenVK) est prévu, voir design/p11-windows.md.

Sous Windows, dans VS Code, Nx Console peut poser NX_WORKSPACE_ROOT_PATH avec un lecteur en minuscule (c:\…) : Vitest charge alors deux copies de lui-même, et chaque test échoue sur « Vitest failed to find the runner ». Posez-la avec un lecteur en majuscule (C:\…) dans le terminal.

Débogage

Section intitulée « Débogage »
  • --validation sur la démo native, ou new VulkanEngine({ validation: true }) : la couche Khronos vérifie chaque appel Vulkan ; device.takeMessages() renvoie ses messages.
  • Un build --debug conserve les symboles : lancez Node sous gdb --args node … pour déboguer l’addon.
  • FDW_NATIVE_ADDON et FDW_VULKAN_ADDON chargent un addon compilé ailleurs.
