Profils et vues

L’éditeur est une application sur une coque ; un viewer, un configurateur, un éditeur de matériaux en sont d’autres. Ils n’ont pas besoin d’une coque à eux : chacun est un profil, les plugins qu’il charge, sa disposition au premier démarrage, les commandes qu’il permet. Et chacun peut montrer la scène dans plusieurs vues, côte à côte, leurs caméras liées.

Voici la coque dans le profil viewer, le viewport partagé en deux. Faites glisser avec le bouton droit dans une vue : l’autre suit. Le menu Edit n’a ni Undo, ni Delete, ni gizmo ; l’inspecteur est en lecture seule.

Ouvrir l'éditeur dans une page à lui

Choisir un profil

Section intitulée « Choisir un profil »

Neuf profils viennent avec l’éditeur :

Profil Plugins Ce qu’il permet
editor Tous, ceux de l’hôte aussi Tout
viewer L’atelier, le viewport, le niveau, l’outliner, l’inspecteur, la console Ouvrir un modèle (Ouvrir un modèle), sélectionner, masquer, isoler, cadrer, mesurer, couper, éclater ; aucune commande qui édite
simulation Ceux du viewer, la simulation Le viewer, et les résultats d’une simulation en contours avec leur légende, déformés, dans le temps (Afficher des résultats de simulation)
render-studio Ceux du viewer, le studio de rendu Le viewer sans mesures, coupes ni explosion, et la mise en scène d’un produit : ses caméras nommées, leurs cadrages, leurs sorties (Mettre en scène un produit), son éclairage (Éclairer un produit), ses matériaux (Assigner des matériaux), son aperçu par le path tracer (Prévisualiser un rendu), ses rendus finaux (Faire le rendu final)
viewer-embedded Le viewport, le niveau La vue et ses barres d’outils, dans une page d’une autre application, pilotée par son API (Intégrer le viewer)
simulation-embedded Le viewport, le niveau, la simulation La vue, sa légende et ses pas, dans une page d’une autre application, pilotés par son API (Intégrer des résultats de simulation)
material-editor L’atelier, les material graphs, la console Les matériaux seuls, en onglets, prévisualisés et comparés, sans scène ni viewport (L’éditeur de matériaux)
material-editor-embedded L’atelier, les material graphs Le matériau, son aperçu et ses paramètres, dans une page d’une autre application, pilotés par son API (De la bibliothèque à l’instance)
configurator Le viewport La vue seule : ni menus, ni docks, ni barre d’état

L’hôte choisit : FDW_PROFILE pour les deux hôtes (lue par Vite pour celui du web), ?profile= dans la page de l’éditeur web, ou EditorHost.profile quand il construit le sien.

Écrire un profil

Section intitulée « Écrire un profil »

Un profil est une simple donnée, un EditorProfile :

  • Les plugins qu’un profil ne liste pas ne sont pas enregistrés : leur manifeste n’est pas lu, leur code jamais importé. Sur le web, le viewer ne télécharge même pas les chunks des éditeurs de graphs.
  • Une commande non permise n’est pas montrée (menus, barres d’outils, palette) et ne s’exécute pas, ni par une touche ni par un plugin : commands.permitted(id) le dit.
  • Ses context keys : profile (son identifiant) et profile.editing, pour les clauses when des plugins. L’inspecteur et l’arbre intégrés lisent profile.editing.
  • Son layout est gardé sous sa propre clé : le viewer ne défait pas le layout de l’éditeur, ni l’inverse. Reset Layout redonne le chrome du profil.

Plusieurs vues

Section intitulée « Plusieurs vues »

Scene → Split the viewport ouvre une autre vue de la scène à côté des autres, jusqu’à quatre ; Scene → Link the cameras choisit si leurs caméras bougent ensemble (elles le font au début). Chaque vue a sa caméra, ses entrées et ses outils : un rectangle se trace dans la vue où il commence, un gizmo tourne dans l’une ou l’autre ; la sélection et l’historique sont ceux du niveau. La caméra de la dernière vue bougée mène ; F cadre la sélection dans la première vue, et les vues liées suivent.

Une vue est une surface du moteur, pas une image copiée : le niveau est une fois sur le GPU (un seul Renderer), et chaque vue le dessine avec sa caméra.

Hôte Backend Une vue est
Web WebGPU Un canvas, sa swapchain sur le même device
Web WebGL2 Un canvas ; le contexte sur un canvas hors écran, copié dans chaque vue
Bureau Vulkan, Direct3D 12 Une fenêtre enfant sur sa zone, sa swapchain sur le même device
Bureau Dawn Une fenêtre enfant, chaque image relue et copiée, comme la première

Une vue à soi

Section intitulée « Une vue à soi »

Un plugin montre une vue du moteur où il veut : son panneau rend le Viewport de l’hôte avec un identifiant à lui. Le moteur crée la vue à ses premières bornes, y dessine la scène, et la détruit quand le composant s’en va.

Le moteur dit si la scène se montre dans la vue (view.state) : le niveau le fait ; une scène de démo n’a qu’une vue, et le panneau le dit.

Une scène de plusieurs vues

Section intitulée « Une scène de plusieurs vues »

Côté moteur, une scène se montre dans d’autres vues quand elle a addView(surface, options) (@fdw/engine-runtime) : une SceneView, dessinée après la première à chaque image, avec linked. Le niveau (LevelView) le fait ; une scène à vous fait de même, une caméra par vue.

Limites : les statistiques de la barre d’état sont celles de la première vue ; les manettes ne pilotent qu’elle ; chaque vue trace ses propres rayons quand le rendu en utilise.
