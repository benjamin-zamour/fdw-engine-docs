L'éditeur

L’éditeur édite les niveaux du moteur : il ouvre une scène, la montre dans un viewport 3D entre ses panneaux, et la modifie avec les outils d’édition (sélection, gizmos, annulation). Il tourne dans deux hôtes qui partagent la même interface :

  • sur le bureau, une application Electron : le moteur rend en natif, sur Vulkan, dans une fenêtre placée dans la zone du viewport ;
  • dans le navigateur, une page web : le moteur tourne dans la page et rend dans un canvas, sur WebGPU ou WebGL2.

Voici celui du web, en direct. Cliquez dans le viewport, puis faites glisser avec le bouton droit pour tourner la caméra, la molette pour zoomer ; un clic sélectionne un objet, W, E et R choisissent l’outil qui le déplace, le tourne ou le met à l’échelle.

Ouvrir l'éditeur dans une page à lui

Les pages suivantes s’en servent : Éditer un niveau parcourt son interface, Écrire un plugin lui ajoute une commande et un panneau, et Le viewport natif explique comment l’éditeur de bureau met le moteur dans sa fenêtre, et ce que cela coûte. Profils et vues fait un viewer de la même coque, et partage le viewport en vues dont les caméras bougent ensemble.

Le lancer

Section intitulée « Le lancer »

Dans le navigateur, depuis la racine du dépôt :

Le même éditeur est aussi construit dans ce site : l’ouvrir dans une page à lui. Son layout est gardé dans IndexedDB ; les fichiers des niveaux sont ouverts et enregistrés par la File System Access API (Chromium), sinon par un import et un téléchargement.

Sur le bureau (Linux, X11 ou XWayland), avec les addons natifs construits, le SDK Vulkan, libX11 et libXext :

L’éditeur de bureau se construit avec la chaîne Electron partagée (tools/electron, hors des workspaces npm), que npx nx run editor-desktop:install installe la première fois. Depuis un terminal de VS Code, retirez ELECTRON_RUN_AS_NODE, qui fait démarrer Electron en Node.

L’exécutable : un exécutable portable sous Windows, une AppImage sous Linux, avec les addons, DXC et les programmes de ses scènes précompilés ; il ne demande ni CMake, ni compilateur, ni SDK Vulkan.

Ses programmes sont compilés en jouant ses scènes sur une surface hors écran, sous Vulkan et Direct3D 12 (Windows) : il faut un périphérique, un GPU ou un logiciel (lavapipe, WARP) ; node scripts/package.mjs --no-precompile n’en livre aucun. L’exécutable n’a pas le repli sur Dawn : Dawn demande un Node à lui.

Le backend

Section intitulée « Le backend »

La variable FDW_BACKEND choisit le backend, lue au démarrage de l’éditeur (par Vite pour celui du web). Sans elle, le premier de chaque hôte ; quand celui demandé ne démarre pas, ou est inconnu, l’autre, et la status bar dit pourquoi.

Hôte FDW_BACKEND Repli Comment les images arrivent à l’écran
Bureau vulkan (défaut) dawn Une swapchain sur la fenêtre du viewport, sans copie
Bureau dawn Un processus Node à lui ; chaque image relue, copiée dans la fenêtre
Web webgpu (défaut) webgl2 Le canvas du viewport
Web webgl2 Le canvas du viewport

Sur le bureau, Dawn tourne dans un processus Node à lui, qui doit être Node 24 : FDW_NODE donne son chemin, sinon le node du PATH. FDW_SCENE choisit la scène montrée d’abord : le niveau par défaut, ou une des scènes de démo du menu Scene (tps, physics, ocean…). FDW_PROFILE choisit l’application sur la coque : editor (par défaut), viewer ou configurator (?profile= dans la page de celui du web) ; voir Profils et vues.

De quoi il est fait

Section intitulée « De quoi il est fait »
  • Le shell (EditorShell) est toute l’interface, en React. Il n’a pas de panneau à lui : le viewport, l’outliner, l’inspecteur, la console, les menus du niveau sont des plugins, intégrés ; un hôte ajoute les siens.
  • Le moteur n’est jamais entre les mains de l’interface. La page et le moteur se parlent par messages (@fdw/editor-ui/protocol) : les bornes du viewport, les entrées, les commandes sur le niveau dans un sens ; l’état du moteur et la projection du niveau dans l’autre. Sur le bureau, le moteur tourne dans un processus utilitaire d’Electron, et ne bloque jamais l’interface ; sur le web, il tourne dans la page, derrière un MessageChannel.
  • Un hôte donne au shell un EditorHost : la connexion au moteur, le composant du viewport (qui reçoit l’identifiant de la vue qu’il montre), les fichiers, le stockage du layout, ses plugins, son profil. Le README de @fdw/editor-ui les liste pour les deux hôtes.
