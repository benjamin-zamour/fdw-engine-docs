@fdw/design-review

Ce contenu n’est pas encore disponible dans votre langue.

Append-only design reviews with anchored threads, companion files, and project catalog integration.
Product Editor
Visibility Public: Meant to be used by applications and plugins.
Domains The editor, Text, drawing and inspection
Dependencies project, view-state
Dependents editor-plugin-design-review, editor-ui
Tests test-unit (npx nx run design-review:<target>, the families of the CI in Testing)
API API reference
Source editor/design-review

The model and stores for a design review: append-only discussion events, versioned companion files, fine-grained anchors, and permissions supplied by the host. Its project store writes reviews as catalogued assets in a @reviews/ project library. Design: specs/design/p28-design-review.md.

Store and append-only history

Section titled “Store and append-only history”

Edits, replies, assignments, labels, resolutions and version changes are new events. reviewThreads derives the current state without deleting the history: an edited comment (comment.edited, by its author only) keeps its earlier bodies in history. filterThreads narrows the threads by state, orphans, anchor, author, assignee, label and part; reviewFacets lists the values the filters offer.

A new version

Section titled “A new version”

rebaseReview(review, comparison, { minConfidence }) follows each anchor through the cascade of the viewer’s version comparison: found by its source key, else by its path, then carried to the element it was matched to (by source key, path and name, or geometry). An element removed, matched below the confidence threshold (0.5 by default), matched twice or not found leaves its thread orphaned, with the reason: never deleted, never moved in silence. serializeReview and parseReview read and write a review companion; ProjectReviewStore.mount keeps the same files in a project library and registers them in its catalog.

Permissions

Section titled “Permissions”

ReviewPermissions is resolved by the host for each operation. The store enforces it as well as the UI; a disabled control is not an authorization boundary.
