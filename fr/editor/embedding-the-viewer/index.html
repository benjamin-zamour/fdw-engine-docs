Intégrer le viewer

Le viewer s’intègre dans une page d’une autre application : un PLM, une boutique, une documentation. C’est le même viewer web, dans un cadre, dans le profil viewer-embedded : la vue et ses barres d’outils, sans menus, ni docks, ni barre d’état. La page le pilote par les commandes de @fdw/viewer-embed et écoute ses événements. Les boutons au-dessus de la vue ci-dessous sont cette page, pas le viewer :

Le viewer démarre…



Intégrer
Section intitulée « Intégrer »




create ajoute un cadre qui remplit l’élément. Le cadre a ?api : le
viewer écoute les commandes de son parent, et seulement de l’origine de
la page (?origin=, mise par create) ; il ne répond qu’à cette
origine. backend impose WebGPU ou WebGL2 ; profile: 'viewer' donne le
viewer entier, avec ses menus et ses panneaux.


Les commandes
Section intitulée « Les commandes »


Chaque commande répond par une promesse, une fois faite ; celles envoyées
avant que le viewer soit prêt l’attendent.






Méthode
Ce qu’elle fait






open(url, name?)
Ouvre un modèle (récupéré par le viewer) : résolue une fois sa géométrie chargée




openData(name, bytes)
La même depuis ses octets : un fichier déposé sur la page




select(paths)
Sélectionne par chemins d’instance ; résolue avec les chemins sélectionnés




frameSelection()
Cadre la sélection, ou le modèle entier




section({ axis, box, clear })
Coupe selon un axe, par une boîte de coupe, ou enlève les coupes




explode({ mode, factor, spread, traces })
Éclate, animé




assemble()
Rassemble, animé




getState()
L’état de visualisation en JSON (fdw.view-state)




setState(document)
Charge un état : les pièces trouvées par leurs ids, puis par leurs clés sources




run(id)
Exécute une commande du viewer (fdw.level.hide…) : si elle a tourné






Une commande que le viewer ne peut pas faire est rejetée par une
ViewerError avec sa raison : un modèle sans lecteur, une erreur du
moteur. run n’exécute que ce que le profil permet : aucune commande qui
édite, dans un viewer.


Les événements
Section intitulée « Les événements »






Événement
Données
Quand






ready
backend
Le viewer écoute




opened
name, parts
Un modèle est ouvert, sa géométrie chargée




selection
paths
La sélection a changé




measures
measures (leur texte)
Une mesure a été prise ou enlevée




error
message
Une erreur du moteur






L’état, depuis la page
Section intitulée « L’état, depuis la page »


getState() donne ce qu’a fait l’utilisateur : les pièces masquées et
colorées, les mesures, les coupes, l’explosion. Gardez-le avec la fiche
du modèle dans votre application, et rendez-le par setState() la fois
suivante : les pièces sont retrouvées par leurs clés sources même quand
le fichier a été relu (voir
L’état de visualisation).




Les messages
Section intitulée « Les messages »


En dessous, la page et le cadre échangent des messages marqués
channel: 'fdw.viewer' : une commande avec un id, à laquelle répond le
même id ; les événements d’eux-mêmes. Un hôte qui n’est pas une page (le
viewer dans une autre fenêtre, un test) sert la même API par
serveViewerApi(runtime, channel) d’@fdw/editor-ui, sur n’importe quel
canal qui envoie et écoute.
