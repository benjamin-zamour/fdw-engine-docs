Écrire une capacité

Le noyau géométrique est un registre léger : chaque opération (kernel.extrude, kernel.tessellate…) est une capacité, nommée et versionnée, fournie par un plugin. Un plugin déclare ses capacités dans un manifeste, lu sans son code ; son code est chargé dans l’hôte (le worker) à son premier usage. Ici, une capacité à nous : un tétraèdre.

Le manifeste

Section intitulée « Le manifeste »

Les capacités du noyau (kernel.primitives, kernel.transform, kernel.extrude, kernel.revolve, kernel.tessellate) vérifient les détails de leurs fournisseurs : les formes de kernel.primitives, les surfaces de kernel.tessellate. Un nouveau nom est libre.

L’opération

Section intitulée « L’opération »

Une opération tourne dans l’hôte : elle reçoit le contexte (la tolérance partagée par tous les plugins) et son entrée, et rend un B-rep du pivot, que l’hôte garde comme un nouveau corps, vérifié. Le body de l’entrée nomme un corps : l’hôte donne son B-rep à l’opération.

BrepBuilder fabrique les identifiants, partage les arêtes droites entre les faces et oriente chaque boucle dans le sens trigonométrique vu de l’extérieur de sa face. Une face courbe donne aussi la courbe de chaque arête dans ses paramètres (ses pcurves, face(surface, sense, loops)) : la tessellation en a besoin sur une couture ou à un pôle.

Les erreurs sont des KernelError, au chemin de l’entrée : un plugin ne rend jamais un B-rep invalide ; ce qu’il lève d’autre devient une erreur failed, avec son message et le plugin. Un plugin qui fournit une capacité du noyau vérifie son entrée avec les vérifications du contrat (checkPrimitive, checkExtrude, checkRevolve, checkTransform, checkTessellate) : la même entrée, la même erreur, quel que soit le plugin.

L’enregistrer

Section intitulée « L’enregistrer »

Dans le worker, à côté du noyau de base ; son code chargé à son premier usage :

Le corps est un corps comme les autres : déplacé, tessellé, donné au pivot. Pour remplacer une capacité du noyau de base, la fournir avec une priority plus haute, ou laisser l’utilisateur choisir (host.capabilities.prefer('kernel.extrude', 'my.plugin')).

La batterie

Section intitulée « La batterie »

Avant d’être accepté, un plugin passe la batterie de cas pathologiques : des entrées dégénérées, des profils ouverts, croisés ou qui traversent leur axe, des transformations auxquelles les surfaces analytiques ne survivent pas, chacun devant échouer avec son code ; et des corps dont la tessellation doit être fermée, tournée vers l’extérieur, du volume attendu. Un plugin ajoute ses propres cas :

checkTessellation(mesh) dit si un maillage est fermé (ses sommets fusionnés, chaque arête partagée une fois dans chaque sens), si ses triangles regardent comme leurs normales, et son volume.
