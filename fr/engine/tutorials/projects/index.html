Les projets et le catalogue

Un niveau qui référence trees/fir.glb casse le jour où le sapin part dans models/conifers/. Dans un projet, chaque asset a un GUID, écrit dans ses métadonnées à côté de sa source (fir.glb.meta), et les scènes référencent asset:<guid> : le chemin peut changer, la référence tient.

Ci-dessous, un projet en mémoire, tel qu’il serait sur un disque : un sapin dont les métadonnées ont été écrites à la main, une fougère qui n’en a pas. Un niveau y est écrit, ses modèles référencés par leurs chemins, réécrits en GUID, puis chargé par le catalogue. Move déplace le sapin et recharge le niveau ; Copy duplique le sapin avec ses métadonnées, comme le ferait un gestionnaire de fichiers ; Fix donne à la copie un GUID à elle.

Le dossier

Section intitulée « Le dossier »

Un projet est un dossier avec son manifeste à la racine, fdw-project.json :

ignore liste les chemins qui ne sont pas des assets ; les noms qui commencent par un point (.git, .fdw) n’en sont jamais. Le dossier est une source qui liste, écrit et supprime aussi : FileSource de @fdw/engine-resources-native sur le bureau, DirectorySource de @fdw/engine-resources-web sur le web (un dossier choisi par showDirectoryPicker), MemoryFolder dans les tests et dans cet exemple.

create écrit le manifeste, et .fdw/.gitignore : le dossier des caches reste hors du gestionnaire de versions. Un dossier sans manifeste est refusé, par une ProjectError de code not-a-project.

Les métadonnées

Section intitulée « Les métadonnées »

Chaque source a ses métadonnées à côté d’elle, un fichier JSON qu’une personne peut lire et qu’un gestionnaire de versions peut comparer :

Le type vient de l’extension (glb : model, scene.json : scene, png : image ; types en ajoute) ; import garde les réglages de l’import, dependencies les GUID que l’asset référence. À l’ouverture, une source sans métadonnées en reçoit, avec un nouveau GUID, et c’est signalé : rien n’est écrit en silence.

Avec missingMeta: 'report', le dossier reste tel quel : la source est signalée (missing-meta) et reste hors du catalogue. Des métadonnées sans leur source sont orphan-meta, des métadonnées illisibles invalid-meta.

Le catalogue

Section intitulée « Le catalogue »

Le catalogue est dérivé des métadonnées, jamais écrit à la main. Il est parcouru à l’ouverture et par refresh() ; les métadonnées dont la révision n’a pas changé sont prises dans un cache, .fdw/catalog.json.

Il se monte dans le store comme une source : asset:<guid> lit la source de l’asset, où qu’elle soit, et ses fragments marchent comme avec un chemin (asset:5b0e…#mesh/0).

Les références d’une scène

Section intitulée « Les références d’une scène »

Une scène écrite par captureScene référence ce qu’elle a chargé par son URI. Capturée avec son chemin dans le projet comme uri, ce qui a été chargé par asset:<guid> reste référencé par GUID, en entier :

Une scène qui arrive avec des chemins (écrite à la main, importée) est réécrite :

Chaque chaîne qui nomme la source d’un asset, relative à la scène ou depuis la racine, devient sa référence asset: ; chaque changement est listé, les données données ne sont pas modifiées. Le format n’a pas besoin d’être connu : les instances, les lots et les données des composants sont tous parcourus. missingAssets(data) liste les références à des GUID que le catalogue n’a pas, avec l’endroit où elles sont.

write(path, bytes) écrit la source et ses métadonnées : un nouvel asset reçoit un nouveau GUID, un asset déjà là garde le sien, et ce qui s’en sert se recharge.

Déplacer

Section intitulée « Déplacer »

La source et ses métadonnées se déplacent ensemble : le GUID reste, le niveau s’ouvre toujours, et ce qui avait été chargé depuis le sapin se recharge depuis son nouveau chemin. Un chemin déjà pris est refusé (exists), rien n’est déplacé.

Les doublons

Section intitulée « Les doublons »

Un fichier copié avec ses métadonnées, par un gestionnaire de fichiers, donne deux sources pour un GUID. Le parcours les trouve : l’asset qui avait le GUID le garde (à l’ouverture, le premier par chemin), la copie est hors du catalogue jusqu’à ce qu’elle ait le sien :

Les références au GUID mènent toujours à l’asset qui l’a gardé.

Les bibliothèques

Section intitulée « Les bibliothèques »

D’autres dossiers rejoignent le catalogue sous un nom : une bibliothèque de matériaux, le magasin des commentaires d’une revue, la destination des rendus.

Leurs GUID sont uniques avec ceux du projet : un doublon entre le projet et une bibliothèque est signalé comme les autres.
