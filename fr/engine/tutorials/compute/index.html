Une grille de 96 × 96 sommets, dont les hauteurs sont calculées sur le GPU à chaque image par un compute graph, puis lues par le matériau de la grille.

…

Sur tous les backends

WebGL2 n’a pas de compute shaders : il exécute le même graphe par rendu dans une texture, sans changer le code (voir En WebGL2).

Un compute graph

Section intitulée « Un compute graph »

Un compute graph utilise les mêmes nœuds qu’un matériau, mais se termine par compute(), et écrit dans des storage buffers au lieu de renvoyer une couleur. Il exécute un thread par élément de travail, regroupés en workgroups : ici un thread par sommet, en workgroups de 8 × 8.

  • global-invocation-id est l’indice du thread, en x, y et z (u32) ; std.convert le convertit en flottants.
  • c.storage(name, arrayType(element)) déclare un buffer : un tableau dont la taille est fixée par le buffer. access: 'read-write' permet au graphe d’y écrire.
  • c.write(array, { index, value, when }) écrit un élément ; when, un booléen, protège les threads situés au-delà de la fin du tableau.

Compilé avec les capacités du backend, le graphe échouerait avec un message clair sur un backend sans compute ; tous les backends du moteur l’ont, WebGL2 par rendu dans des textures.

Le compilateur refuse ce qui ne peut pas fonctionner dans un compute shader : std.textureSample (il a besoin des dérivées d’un fragment shader : utilisez std.textureSampleLevel), et la lecture d’un buffer que le graphe écrit, puisque les threads s’exécutent dans un ordre quelconque.

L’exécuter

Section intitulée « L’exécuter »

dispatch lie les valeurs par leur nom — uniforms, textures, samplers, storage buffers — et soumet workgroups groupes de threads. Le GPU exécute les soumissions dans l’ordre : l’image dessinée ensuite voit les nouvelles hauteurs.

workgroups peut aussi être un buffer écrit par le GPU, { buffer, offset }, contenant trois u32 : un dispatch indirect (pas en WebGL2).

Pour lire les résultats sur le CPU, donnez au buffer l’usage copy-src et faites await buffer.read(), qui se résout avec un ArrayBuffer.

Section intitulée « Lire le buffer dans un matériau »

positionOffset déplace les sommets, dans l’espace de l’objet. La hauteur est lue par l’étape de sommets, puis interpolée pour la couleur : le compilateur place chaque calcul dans l’étape où ses entrées sont disponibles.
