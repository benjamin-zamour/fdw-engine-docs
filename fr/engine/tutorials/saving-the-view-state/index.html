Enregistrer l'état

L’état de visualisation d’un modèle, ses couleurs, ses coupes, ses vues de caméra, ses annotations, vit en mémoire. Pour le retrouver demain, il est écrit dans un fichier compagnon à côté du modèle : bracket.glb.view.json pour bracket.glb. Un fichier JSON qu’une personne lit, et qu’un gestionnaire de versions compare ; le modèle lui-même n’est jamais modifié.

Ci-dessous, un état est fait sur une première lecture du modèle, écrit, puis relu après une nouvelle lecture du modèle : ses identifiants ont changé, les pièces sont retrouvées par leurs clés sources. Ce qui est dessiné est l’état relu.

Écrire

Section intitulée « Écrire »

ViewStatePersistence tient les exporteurs et les importeurs de l’état, déclarés par des plugins. Le fichier compagnon est celui par défaut :

Le fichier contient tout l’état, et le nom du modèle pour lequel il a été écrit :

Écrit pour une comparaison : deux espaces, un vecteur ou un chemin sur une ligne, une ligne à la fin, et les mêmes octets pour le même état. Masquer une pièce ajoute une ligne ; relire le fichier et le réécrire ne change rien.

Relire

Section intitulée « Relire »

import choisit l’importeur par la fin du nom du fichier, lit le fichier et remplace le contenu de l’état. Les éléments sont ensuite trouvés par resolve, comme toujours : par leurs identifiants, puis par leur clé source quand le modèle a été relu (source-key-fallback, dit, et les références prennent les nouveaux identifiants : le prochain export les écrit).

Un fichier écrit pour un autre modèle (bracket.glb.view.json lu pour bracket-v2.glb) est lu quand même, avec un avertissement : ses éléments sont trouvés là où leurs identifiants ou leurs clés correspondent encore.

Le rapport, et le mode strict

Section intitulée « Le rapport, et le mode strict »

Rien ne se perd en silence. Le rapport (ViewStateReport) a une ligne pour ce qui n’a pas été gardé tel quel :

  • une annotation d’un type qu’aucun plugin ne déclare ici : gardée telle que lue, non affichée, réécrite inchangée (un avertissement, pas une perte) ;
  • une annotation que son type refuse, une section ou une vue invalide : écartée (une perte) ;
  • ce qu’un exporteur n’écrit pas : perdu, dit avant qu’il ne tourne.

Par défaut le mode est permissive : ce qui peut être lu l’est. En mode strict, la première perte lève une ViewStateError (strict, avec sa ligne) : l’état est inchangé, rien n’est écrit.

D’autres formats

Section intitulée « D’autres formats »

Un exporteur ou un importeur est un plugin déclaré par le manifeste commun (@fdw/capabilities), comme les lecteurs du pivot : ses formats, ses extensions, sa forme (companion, ou embedded dans le fichier du modèle), et les parties de l’état qu’il tient (looks, isolation, annotations, views, sections). Celles qu’il ne tient pas sont dites perdues.

Le plugin travaille sur l’état en JSON (ViewStateDocument) : son exporteur en fait des fichiers, son importeur en fait un d’un fichier. L’état dans le fichier du modèle lui-même, écrit par la conversion du pivot, viendra avec les extensions du pivot.
