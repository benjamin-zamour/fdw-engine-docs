Un terrain procédural

Un matériau procédural vit sur le GPU, mais le jeu vit sur le CPU : la physique a besoin des hauteurs du sol, le placement des objets a besoin de savoir où pousse la mousse. @fdw/engine-noise calcule les mêmes bruits en TypeScript que le material graph : les mêmes hachages entiers, les mêmes algorithmes, les mêmes constantes.

Dans l’exemple, les hauteurs viennent du CPU ; le sol est peint par le GPU : de l’herbe, une mousse sombre là où un fbm est haut, de la roche sur les pentes. Le CPU calcule le même fbm pour poser des rochers sur la mousse, et seulement là.

Les hauteurs, sur le CPU

Section intitulée « Les hauteurs, sur le CPU »

Le terrain de la tessellation prend ses hauteurs de 0 à 1 dans un tableau. Une somme ridged fait les crêtes, un fbm les collines :

Les options sont celles des macros du graphe : noise, octaves, lacunarity, gain, seed, footprint. Les bruits prennent des tableaux de 2, 3 ou 4 coordonnées (valueNoise, perlinNoise, simplexNoise, worleyNoise, ou noise(kind, point)), et les hachages sont là aussi (pcg, pcg3d, hashCell, random). La physique lit le même tableau : dans le jeu à la troisième personne, le heightfield de la forêt en vient.

Le sol, sur le GPU

Section intitulée « Le sol, sur le GPU »

Le matériau lit la position dans le monde et calcule la mousse avec le même fbm, à la même échelle, avec la même graine :

L’herbe a une fine variation à elle, effacée là où elle est plus petite qu’un pixel (filtered: true, voir Les matériaux procéduraux).

Les rochers, sur le CPU

Section intitulée « Les rochers, sur le CPU »

Un candidat par cellule de 5 m, déplacé dans sa cellule par un aléa de la cellule (random : des flottants dans [0, 1) par cellule entière, comme noise.random2…4 sur le GPU), gardé là où le fbm dépasse 0,3, là où la mousse est pleine :

Aucune texture n’est relue depuis le GPU, aucune table n’est partagée : les deux côtés calculent le bruit. Les rochers tombent sur la mousse quelles que soient la graine, l’échelle ou le nombre d’octaves, du moment que les deux côtés utilisent les mêmes.

L’écart entre les deux côtés

Section intitulée « L’écart entre les deux côtés »

Les hachages sont égaux au bit près : les entiers du CPU (Math.imul, >>>) bouclent comme les u32 du GPU. Les flottants diffèrent : le CPU calcule en doubles, le GPU en flottants, et le GPU peut fusionner un produit et une somme. Les valeurs concordent à environ 10⁻⁵ près ; un seuil sur un bruit est franchi au même endroit, à quelques micromètres près. Seule la cellule d’un bruit de Worley peut changer, là où deux points sont à la même distance.

Les tests de rendu le vérifient sur chaque backend : un compute graph évalue chaque bruit, chaque dimension et chaque somme fractale en des points d’échantillon, le CPU évalue les mêmes, et ils sont comparés — sur Dawn, sur Vulkan et en WebGL2.

La roche des pentes

Section intitulée « La roche des pentes »

La roche est la texture cuite dans Les matériaux procéduraux, lue en mapping triplanaire : sur une pente, les uv d’un terrain s’étirent, les trois plans du monde non.

Sans position, triplanarTexture lit à la position dans le monde ; la normale est celle de la carte des hauteurs, par pixel (terrainBase). La hauteur de la roche, dans son alpha, incline la normale par bump mapping.
