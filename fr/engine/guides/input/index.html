Entrées

Trois packages lisent le clavier, le pointeur et les manettes, de la même façon dans une page et dans une fenêtre native :

Package Contenu
@fdw/engine-input L’état des périphériques (Input), les actions (ActionMap)
@fdw/engine-input-web WebInputSource : les événements DOM, la Gamepad API
@fdw/engine-input-native NativeInputSource : une NativeWindow, les manettes de SDL3

Le cœur ne dépend ni du DOM ni de SDL : une application choisit sa source, et le reste de son code est le même partout.

Une source, une entrée, une frame

Section intitulée « Une source, une entrée, une frame »
  • WebInputSource(target) écoute un élément — un canvas : donnez-lui un tabindex pour qu’il reçoive les touches une fois cliqué — ou toute la window.
  • NativeInputSource(window) écoute une NativeWindow. Ses événements sont lus par runLoop, comme les autres événements de la fenêtre.

update() applique les événements reçus depuis la frame précédente, lit les manettes, puis l’état ne change plus jusqu’au update() suivant : tout le code d’une frame voit les mêmes entrées.

  • pressed et released sont vrais pendant la frame de l’appui ou du relâchement. Un appui plus court qu’une frame — enfoncé et relâché entre deux mises à jour — n’est pas perdu : pressed est vrai, isDown faux.
  • Les répétitions d’une touche maintenue ne sont pas de nouveaux appuis.
  • Lorsque la page ou la fenêtre perd le focus, tout est relâché : une touche relâchée ailleurs ne reste pas enfoncée.
  • Avec un pas fixe, un appui est vu par chaque pas de sa frame : réagissez-y une fois par frame, en dehors des pas.

Le clavier : des positions, pas des lettres

Section intitulée « Le clavier : des positions, pas des lettres »

Les touches sont nommées par leur position sur le clavier, comme le code du DOM : KeyW, ArrowUp, ShiftLeft, Space, Digit1. Sur un clavier AZERTY, la touche KeyW est Z : un jeu lié à KeyW, KeyA, KeyS, KeyD s’y joue avec ZQSD, sans configuration. Dans une fenêtre native, SDL donne les mêmes positions (ses scancodes), nommées de la même façon.

Pour montrer une touche à l’utilisateur, input.keyboard.label('KeyW') donne ce qu’elle produit dans la disposition du clavier (Z), une fois qu’elle a été appuyée — son code avant cela.

Le pointeur

Section intitulée « Le pointeur »

input.pointer donne x et y de 0 à 1 sur la surface, depuis le coin supérieur gauche, moved pendant la frame, les boutons (isDown(0) : 0 est le bouton principal, 1 celui du milieu, 2 le secondaire), dx et dy : son déplacement pendant la frame, en fractions de la surface (0 avant son premier mouvement), et wheel : les crans tournés pendant la frame, positifs vers le bas.

input.lockPointer() verrouille le pointeur — caché, ses mouvements relatifs et sans limite, pour une vue à la première personne — et lockPointer(false) le libère. pointer.locked dit quand la source l’a obtenu : un navigateur ne l’accepte qu’après un clic ou une touche, et le libère sur Échap. Verrouillé, x et y restent, dx et dy bougent toujours. Voir Contrôles à la première personne.

Les manettes

Section intitulée « Les manettes »

input.gamepads liste les manettes connectées, dans la disposition standard de la Gamepad API et de SDL3 — les mêmes boutons aux mêmes endroits sur toutes les manettes :

Boutons Axes
south, east, west, north (A, B, X, Y sur Xbox) leftX, leftY, rightX, rightY
leftShoulder, rightShoulder de -1 à 1, y positif vers le bas
leftTrigger, rightTrigger, analogiques
back, start, guide, leftStick, rightStick
dpadUp, dpadDown, dpadLeft, dpadRight
  • value(button) va de 0 à 1 (analogique pour les gâchettes) ; un bouton est enfoncé au-delà de 0.5.
  • stick('left') donne { x, y } à travers une zone morte radiale (deadZone, 0.15 par défaut) : un stick au repos n’est jamais exactement à 0. La zone porte sur la longueur du vecteur, de sorte que les diagonales gardent leur direction, et la valeur est remise à l’échelle au-delà, de sorte qu’elle ne saute pas.
  • Dans un navigateur, une manette n’apparaît qu’une fois un bouton appuyé (une règle des navigateurs, contre le fingerprinting) ; seules celles de la disposition standard sont lues.

gamepad.rumble(strong, weak, duration) fait vibrer une manette : son moteur fort (basse fréquence) et son moteur faible (haute fréquence) de 0 à 1, pendant duration secondes. Sans moteurs, ou dans un navigateur sans vibrationActuator, rien ne se passe.

input.lastDevice est le périphérique utilisé en dernier — 'keyboard', 'pointer' ou 'gamepad' : pour viser avec la souris ou un stick, ou pour afficher les bons boutons.

Les actions

Section intitulée « Les actions »

Une application ne devrait pas lire KeyW ou leftX çà et là. Elle déclare des actions, et leurs liaisons :

Type Lecture Liaisons
button button(name) : down, pressed, released, value Touches, boutons du pointeur, boutons de manette
axis axis(name) : un nombre Un axe de stick, pointer:wheel, pointer:deltaX, ou { negative, positive }
vector vector(name) : { x, y }, longueur de 0 à 1, y vers le haut ou l’avant { up, down, left, right }, un stick, ou pointer:delta

Les contrôles sont des chaînes — ils s’enregistrent et se comparent tels quels :

Contrôle Signification
key:<code> Une touche, par position : key:KeyW, key:ArrowUp
pointer:<button> Un bouton du pointeur : pointer:0
pointer:wheel La molette, un axe : les crans de la frame
pointer:delta Le déplacement du pointeur pendant la frame, un vecteur
pointer:deltaX, deltaY Le même, en axes (y positif vers le bas)
pointer:locked Un bouton, enfoncé tant que le pointeur est verrouillé
gamepad:<button> Un bouton de manette : gamepad:south, gamepad:rightTrigger
gamepad:<axis> Un axe de stick, à travers sa zone morte : gamepad:leftX
gamepad:leftStick, rightStick Un stick, pour un vecteur (comme bouton : le stick enfoncé)
  • Plusieurs liaisons par action : la plus forte l’emporte — le clavier et un stick ne s’additionnent pas. Un bouton est enfoncé lorsque l’un de ses contrôles l’est.
  • Les quatre touches d’un vecteur sont normalisées : la diagonale n’est pas plus rapide.
  • Un vecteur va vers le haut : y est positif vers l’avant, alors que l’axe brut d’un stick est positif vers le bas. La liaison d’un stick le retourne.
  • Toutes les manettes pilotent les actions par défaut. Pour un jeu avec une manette par joueur, new ActionMap(input, definitions, { gamepad: 1 }) ne lit que la deuxième. actions.rumble(strong, weak, duration) fait vibrer les manettes des actions.

Les contextes

Section intitulée « Les contextes »

Un menu et un jeu lisent les mêmes touches différemment : donnez à chacun son ActionMap, et activez-en une à la fois. Désactivée (enabled = false, ou l’option enabled: false), une table ne lit rien : boutons relâchés, axes et vecteurs à 0. Une table activée pendant une frame ne lit rien jusqu’au update() suivant : l’appui qui a ouvert un menu n’agit pas aussi dedans. active dit si la table lit ses actions dans cette frame.

Tests et rejeux

Section intitulée « Tests et rejeux »

FakeInputSource est une source pilotée par le code : keyDown(code), keyUp(code), connectGamepad(), setButton(), setAxis(), et sink pour le pointeur. Elle teste la logique d’une application sans navigateur ni fenêtre, et rejoue des entrées enregistrées.

Une source à soi

Section intitulée « Une source à soi »

Une InputSource écrit les événements dans l’InputSink que Input donne à son attach(), et remplit les états des manettes dans readGamepads(out), en réutilisant les objets de out : rien n’est alloué par frame. setPointerLock(locked) et rumble(gamepad, strong, weak, duration) sont facultatives : une source qui ne les a pas ne verrouille jamais le pointeur ni ne fait vibrer de manette ; avec elles, elle dit au récepteur quand le verrou est pris ou perdu (pointerLock(locked)), et donne les mouvements relatifs dans pointerMove(x, y, dx, dy). Un écran tactile, un rejeu réseau ou une autre bibliothèque de fenêtrage sont une source de plus.

La navigation de la caméra

Section intitulée « La navigation de la caméra »

@fdw/engine-camera déplace une caméra par des actions : OrbitOperator tourne autour d’un point, FlyOperator vole ou marche, avec des liaisons par défaut pour le clavier, la souris et les manettes. Voir le tutoriel Navigation de la caméra.
