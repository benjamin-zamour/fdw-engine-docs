Scene outputs

The scene passes can write more than a color. Here they also write, for each pixel, the normal of the surface, its distance to the camera and the identifier of the object, each into its own texture (multiple render targets). A full screen pass shows the four, one per quarter of the screen.

…

These textures are what screen space effects (ambient occlusion, reflections, outlines), deferred rendering and selection under the mouse are made of. The engine does not fix their list: you choose what each one holds.

Asking for outputs

Section titled “Asking for outputs”

addScenePasses takes outputs, by name. Each one has a format and a value: what it holds.

The opaque pass writes the color and the outputs at once: the objects are drawn a single time. Each output is a texture of the graph, of the size of the color target, cleared to 0 where there is no object.

The simplest values are given by name, and converted to the format:

Value What is written
'view-normal', 'world-normal' The normal of the surface, after normal mapping
'view-depth' The distance to the camera along its axis
'world-position' The position in the world
'object-id' The id of the item (a u32, for an r32uint target)
'base-color', 'roughness', … An input of the surface, or its default

Outputs of your own: function graphs

Section titled “Outputs of your own: function graphs”

A texture of rgba8unorm holds values from 0 to 1: a normal, from −1 to 1, needs encoding. An output can be a function graph: its inputs are named after the values of the surface (viewNormal, viewDepth, objectId, baseColor, roughness…), its output is written, the same for every material.

The function gives the type of the format: a vec4f for rgba8unorm, an f32 for r8unorm, a u32 for r32uint. The example turns the identifier into a color the same way, to see it:

To find the object under the mouse, write 'object-id' into an r32uint target and read the pixel back instead: see Picking. Identifiers go from 1 to 2^24; for more objects, select by ray casting (scene.raycast).

What to know

Section titled “What to know”
  • Transparent items only blend their color: they write no output. A glass object leaves the outputs of what is behind it, and cannot be selected through object-id.
  • Without target, the passes only write their outputs, without the shading models: a G-buffer, for deferred rendering.
  • Limits: 4 targets at least, 8 on most GPUs (capabilities.maxColorAttachments); 32 bytes per pixel in WebGPU (maxColorAttachmentBytesPerSample).
  • Multisampling: the outputs are multisampled with the color and resolved; integer outputs cannot be: draw them with samples: 1.
