Projects and the catalog

A level that references trees/fir.glb breaks the day the fir moves to models/conifers/. In a project, each asset has a GUID, written in its metadata beside its source (fir.glb.meta), and the scenes reference asset:<guid>: the path can change, the reference holds.

Below, a project in memory, as it would be on a disk: a fir whose metadata was written by hand, a fern without any. A level is written in it, its models referenced by their paths, rewritten to their GUIDs, then loaded through the catalog. Move takes the fir elsewhere and reloads the level; Copy duplicates the fir with its metadata, as a file manager would; Fix gives the copy a GUID of its own.

The folder

Section titled “The folder”

A project is a folder with its manifest at the root, fdw-project.json:

ignore lists the paths that are not assets; the names starting with a dot (.git, .fdw) never are. The folder is a source that also lists, writes and removes: FileSource of @fdw/engine-resources-native on the desktop, DirectorySource of @fdw/engine-resources-web on the web (a folder picked with showDirectoryPicker), MemoryFolder in tests and in this example.

create writes the manifest, and .fdw/.gitignore: the folder of the caches stays out of version control. A folder without a manifest is refused, with a ProjectError of code not-a-project.

The metadata

Section titled “The metadata”

Each source has its metadata beside it, a JSON file a person can read and a version control system can diff:

The type comes from the extension (glb: model, scene.json: scene, png: image; types adds others); import keeps the settings of the import, dependencies the GUIDs the asset references. At the opening, a source without metadata gets one, with a new GUID, and it is reported: nothing is written in silence.

With missingMeta: 'report', the folder is left as it is: the source is reported (missing-meta) and stays out of the catalog. Metadata without its source is orphan-meta, metadata that cannot be read invalid-meta.

The catalog

Section titled “The catalog”

The catalog is derived from the metadata, never written by hand. It is scanned at the opening and by refresh(); the metadata whose revision did not change are taken from a cache, .fdw/catalog.json.

It is mounted in the store as a source: asset:<guid> reads the source of the asset, wherever it is, and its fragments work as with a path (asset:5b0e…#mesh/0).

The references of a scene

Section titled “The references of a scene”

A scene written by captureScene references what it loaded by its URI. Captured with its path in the project as its uri, what was loaded by asset:<guid> stays referenced by GUID, whole:

A scene that comes with paths (written by hand, imported) is rewritten:

Each string that names the source of an asset, relative to the scene or from the root, becomes its asset: reference; each change is listed, the data given is not modified. The format does not need to be known: the instances, the batches and the data of the components are all visited. missingAssets(data) lists the references to GUIDs the catalog does not have, with where they are.

write(path, bytes) writes the source and its metadata: a new asset gets a new GUID, an asset already there keeps its own, and what uses it reloads.

Moving

Section titled “Moving”

The source and its metadata move together: the GUID stays, the level still opens, and what was loaded from the fir reloads from its new path. A path that is taken is refused (exists), nothing moved.

The duplicates

Section titled “The duplicates”

A file copied with its metadata, by a file manager, gives two sources with one GUID. The scan finds them: the asset that had the GUID keeps it (at the opening, the first by path), the copy is out of the catalog until it has its own:

The references to the GUID still lead to the asset that kept it.

Libraries

Section titled “Libraries”

Other folders join the catalog under a name: a library of materials, the store of the comments of a review, the destination of the renders.

Their GUIDs are unique with those of the project: a duplicate between the project and a library is reported like any other.
